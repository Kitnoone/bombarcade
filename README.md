# Bombarcade — корабельный терминал

Два кооперативных испытания для Imperium Maledictum. Наблюдатель видит карту и код на телевизоре, оператор управляет зондом и вводит символы с телефона. Оформление корпуса взято из эскиза № 2; карта, клавиши, код и таймеры работают как живые элементы.

## Запуск в Windows

1. Распакуй архив целиком в любую папку.
2. Один раз установи **Node.js LTS 22 или новее** с [nodejs.org](https://nodejs.org/). Оставь включённым **Add to PATH**. Для разработки и всех проверок рекомендуется Node 24.
3. Дважды нажми **«Запустить Bombarcade.bat»**. Откроется терминал наблюдателя в браузере.
4. Если Windows спрашивает о доступе Node.js к сети, разреши доступ для **частных сетей**. Окно сервера оставь открытым до конца партии.
5. Подключи телефон к тому же роутеру. Компьютер может работать по кабелю, а телефон по Wi-Fi.
6. На телевизоре выбери сетевой адрес (обычно **Ethernet / Wi-Fi · рекомендуется**) и отсканируй QR-код телефоном.
7. Дождись надписи **«Телефон подключён»** и нажми **«Начать испытание»**.

После установки Node игра в локальном режиме работает **без интернета**. Сервер, WebSocket, изображения, шрифты и QR-библиотека находятся в комплекте. Дополнительные npm-пакеты для игры не нужны.

Если браузер не открылся сам, используй адрес из окна сервера: обычно `http://localhost:4173/?view=host`. Это адрес для компьютера. Телефон получает другой адрес — например `http://192.168.1.84:4173/?view=phone&room=…&key=…`. Ссылка и QR содержат текущий IP, порт и ключ конкретного сеанса.

**Если телефон не подключается:**

- Выбери другой адрес в списке. VPN и виртуальные адаптеры стоят в конце.
- Проверь, что телефон находится в домашней/клубной сети, а не в гостевой Wi-Fi-сети с изоляцией клиентов.
- Разреши Node.js в брандмауэре Windows для частной сети. При стороннем брандмауэре разреши входящий TCP-порт, указанный сервером.
- Скопируй показанную ссылку целиком и открой на телефоне. Не заменяй её на localhost.
- После смены сети компьютера перезапусти сервер и отсканируй новый QR-код.

Сервер слушает `0.0.0.0`. Порт по умолчанию 4173; если он занят, выбирается следующий свободный из десяти. Запуск из командной строки:

```sh
node server.mjs
node server.mjs --port=4180 --no-open
```

`bombarcade.config.json` задаёт порт, автооткрытие браузера, количество вирусов и длительность их шага. Для остановки закрой серверное окно или нажми Ctrl+C.

## Правила и управление мастера

**Протокол I.** Телевизор показывает стрелки 10 секунд. Затем даёт 20 секунд на ввод. На телефоне девять клавиш 3 × 3: четыре стрелки и пять отвлекающих глифов. После каждого нажатия все клавиши перемещаются. Длина последовательности настраивается от 4 до 12 символов, по умолчанию 8. Неверный символ или тайм-аут прерывает попытку. Этот этап можно повторять без ограничения.

После успеха оба экрана плавно переходят ко второму протоколу за 1,8 секунды, сохраняя сеанс.

**Протокол II.** Зонд движется по полю 18 × 12 четырьмя стрелками. Одно нажатие — один шаг. Видно только два гекса вокруг зонда; разведанные клетки снова уходят в туман. Наблюдатель ищет янтарный ромб среди узлов и направляет оператора голосом. Телефон не получает карту, координаты, положение угроз или правильный код.

На поле три вируса. Попав в радиус обзора, вирус просыпается и начинает погоню по допустимым переходам. Он продолжает двигаться и вне видимости, по одному шагу раз в 800 мс. При обнаружении возникает предупреждение; телефон получает только общую тревогу. Столкновение с зондом завершает попытку. Генератор сохраняет безопасный старт и маршрут к цели без обязательного пробуждения вирусов.

При попадании на цель телевизор показывает восемь цифр 0–9 в течение 10 секунд, после чего даёт **40 секунд** на ввод с телефона. Цифровая клавиатура не перемешивается. Зонд и вирусы во время показа и ввода заморожены.

Во втором протоколе **три попытки**. Захват вирусом, неверная цифра или истечение времени расходуют ровно одну. Кнопка **«Повторить этап»** запускает новый поиск с новой расстановкой, без повторения протокола I. После третьего поражения обычный повтор заблокирован; мастер может выбрать **«Новый полный запуск»**.

Панель мастера открывается внизу экрана. Она позволяет менять число вирусов (0–6), шаг (300–3000 мс), длину первого кода, повторять этап, полностью перезапускать игру и отвязывать телефон в LAN-сеансе. Настройки угроз меняются между попытками; сохраняются на время сеанса. Для постоянных значений отредактируй конфигурационный файл перед запуском сервера.

- **Enter:** начало / повтор доступного испытания.
- **Пробел:** пауза / продолжение.
- **Esc:** закрытие панели мастера.

Сворачивание телевизионного окна и потеря связи автоматически ставят активное испытание на паузу. Во время паузы таймеры и вирусы не двигаются, попытки не расходуются. Переподключение выполняется автоматически; продолжение подтверждает мастер после восстановления обоих экранов. Перезагрузка телефонной вкладки сохраняет её привязку. После перезапуска самого сервера создаётся новый сеанс.

Наверху доступны звук, полный экран и **«Меньше эффектов»**. Учитывается системное предпочтение уменьшенного движения. На локальном HTTP работает генерация идентификаторов и запасное копирование ссылки; кнопка запрета гашения экрана показывается только в поддерживаемом защищённом контексте. На обычном HTTP при необходимости отключи автоблокировку в настройках телефона.

## Три способа соединения

1. **Локальный сервер:** определяется по `/api/local`; логикой управляет компьютерный сервер, устройства используют постоянные WebSocket-соединения. Команды имеют номер, поток и идентификатор попытки, повторные и устаревшие команды отбрасываются. До трёх ходов зонда могут находиться в полёте; переставляемая клавиатура ждёт подтверждения. Диагностика показывает измеренный RTT телефона до сервера.
2. **Интернет:** при запуске со статического хостинга, например [GitHub Pages](https://kitnoone.github.io/bombarcade/public/), используется прежний HTTPS-ретранслятор из `public/config.js`. Движок работает на телевизионном браузере. Игрокам достаточно открыть сайт: Node.js и локальный сервер им не нужны.
3. **Проверка на одном компьютере:** кнопка на входе открывает сеанс с BroadcastChannel. Консоль нужно открыть в другом окне того же браузерного профиля. Этот режим не соединяет разные устройства.

GitHub Pages не запускает локальный сервер. QR локальной партии ведёт на компьютер мастера, а QR интернет-партии — на статический сайт.

## Проверки разработки

```sh
npm test
npm run check
```

41 проверка движка и серверных протоколов покрывает длительности, перемешивание, вирусы, безопасные расстановки, столкновения, заморозку, попытки, паузы, дубликаты, устаревшие сообщения и отсутствие решения в телефонном состоянии.

Для повторения браузерной проверки установи Playwright как инструмент разработки (`npm install --no-save playwright`) и Chrome. Затем:

```sh
npm run test:browser
npm run test:fallback
```

Первая проверка запускает временный сервер на сетевом IPv4-адресе компьютера и независимые контексты Chrome для телевизора 1920 × 1080 и телефона 360 / 390 / 430 пикселей. Она сохраняет скриншоты и отчёт в `test-results/`. Нужен физический сетевой адаптер. Вторая проверяет BroadcastChannel и реальный обработчик ретранслятора с временной локальной SQLite, не обращаясь к живому облачному сервису. Для уже установленной копии Playwright можно задать `PLAYWRIGHT_MODULE` как URL его ES-модуля.

**Физический телефон и реальный Wi-Fi RTT не проверялись.** Сетевая браузерная проверка на IP компьютера подтверждает HTTP/WebSocket и работу без secure-context API; она не является замером задержки между разными устройствами. На роутере требуется проверить доступность компьютера с телефона и фактический RTT. Свежие результаты и изображения находятся в `WORK_REPORT.md` и папке скриншотов готового комплекта.

## Публикация

Проверки запускаются на pull request и при обновлении main. Существующая публикация Pages из корня main сохраняет прежний адрес сайта. Workflow также поддерживает публикацию через **Settings → Pages → Source: GitHub Actions**. Локальный сервер для интернет-версии запускать не требуется.

## Состав и лицензии

- `public/`: оба интерфейса, движок, транспорт и локальные ресурсы.
- `server.mjs`, `server/`: локальный HTTP/WebSocket-сервер и сеансы.
- `relay/`: прежний облачный обработчик; его логика не изменена.
- `design/reference-terminal.png`: предоставленный основной эскиз.
- `tools/build_assets.py`: пересборка графических слоёв из эскиза; только для разработки, требует Pillow, NumPy, OpenCV. Для самой игры Python не нужен.
- `tests/`: проверки логики и транспорта; `tools/verify-*.mjs`: браузерные проверки.

Локальные Oswald, JetBrains Mono и Cinzel распространяются под OFL: `public/fonts/LICENSE-fonts.txt`. QR Code Generator 1.4.4, Kazuhiko Arase, MIT: лицензия в `public/vendor/`. Старая PeerJS сохранена с лицензией, но не загружается и не используется.
