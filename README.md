# Bombarcade — корабельный терминал

Первое кооперативное испытание для финала приключения **Imperium Maledictum**. Компьютер с телевизором показывает последовательность. Второй игрок вводит её на телефоне. Это игровая условность, без реальных схем устройства.

## Игра

**Адрес игры: [kitnoone.github.io/bombarcade](https://kitnoone.github.io/bombarcade/).** Открой его на компьютере и телефоне. Интернет может быть разным: кабель, Wi-Fi или мобильная сеть. QR-код ведёт на телефонную консоль по этому же адресу GitHub Pages.

1. На компьютере открой игру на GitHub Pages и нажми **«Создать сеанс»**. Выведи окно браузера на телевизор.
2. На телефоне отсканируй QR-код или открой тот же сайт и введи шестизначный код.
3. Дождись надписи **«Телефон подключён»**, выбери длину последовательности (по умолчанию 8) и нажми **«Начать испытание»**.
4. **10 секунд:** на большом экране виден весь порядок стрелок. Телефон заблокирован. Наблюдатель запоминает и передаёт команды.
5. **15 секунд:** последовательность исчезает. На телефоне открывается клавиатура **3 × 3**: `↑ ↓ ← → Æ Œ Þ Ð Ƶ`. После любого нажатия все девять клавиш перемещаются, ни одна не остаётся на прежнем месте.
6. Правильный ввод открывает первый шлюз. Неверный символ, глиф или истёкшее время завершают попытку. Новую попытку запускает мастер на большом экране.

На телефоне нет решения: сетевые сообщения содержат раскладку клавиш, введённые символы и состояние таймера. Правильность проверяется на компьютере. Следующее испытание пока не реализовано; успешный ввод завершает только первый протокол.

**Пауза:** мастер может остановить таймер. При потере связи с телефоном или сворачивании большого экрана таймер автоматически останавливается. После восстановления связи мастер нажимает **«Продолжить»**. Не сворачивай телевизионное окно во время игры. Телефон может запросить запрет гашения экрана кнопкой внизу (если браузер поддерживает Screen Wake Lock).

**Проверка без телефона:** кнопка **«Проверить на одном компьютере»** создаёт отдельный локальный сеанс. Открой консоль в отдельном окне того же браузера, поставь окна рядом. Этот режим использует BroadcastChannel и не соединяет разные устройства. Обычный режим использует настоящую сетевую связь.

## Публикация на GitHub Pages

Игра публикуется на GitHub Pages автоматически. Workflow загружает стартовую страницу и папку `public` в той же структуре, что и публикация из корня ветки. Стартовая страница открывает `public/`, сохраняя параметры комнаты. Оба способа ведут к игре на GitHub. Ничего устанавливать игрокам не нужно.

Однократно открой [Settings → Pages](https://github.com/Kitnoone/bombarcade/settings/pages), выбери **Build and deployment → Source → GitHub Actions**. Затем в [Actions](https://github.com/Kitnoone/bombarcade/actions) выбери **Verify and publish → Run workflow → main**. После успешного задания `deploy` сайт доступен по адресу:

**https://kitnoone.github.io/bombarcade/**

Пока Pages не включён, workflow проверяет код и пропускает публикацию, оставляя инструкцию в сводке. Последующие коммиты в `main` автоматически проверяются и публикуются. Доступный GitHub-коннектор умеет записывать код, но не изменяет настройки Pages; включение Source выполняет владелец репозитория.

## Связь между устройствами

Версия **0.2** использует общий HTTPS-сервер сеансов. Прямое WebRTC-соединение больше не требуется. Компьютер и телефон могут находиться в разных сетях: кабель + Wi-Fi, домашний интернет + мобильный интернет или два разных провайдера. Достаточно открыть приложение и соединиться по QR-коду или коду комнаты.

Сервер: **https://bombarcade-relay.kittyty.chatgpt.site**. Он хранит временные комнаты и передаёт команды и состояние между двумя браузерами. Проверка правильности остаётся на телевизионном компьютере; правильная последовательность на сервер и телефон не отправляется. Комнаты удаляются после двух часов без активности компьютера. При закрытии или недоступности одного экрана испытание останавливается.

У каждой консоли есть отдельный случайный ключ доступа, сохраняемый в sessionStorage и передаваемый в HTTPS-заголовке. В базе хранятся только хеши ключей. Код комнаты не позволяет читать состояние или управлять экраном мастера; первая подключившаяся консоль занимает слот оператора. Повторные HTTP-запросы с одной командой не создают повторного ввода.

Обмен идёт через короткие HTTPS-запросы примерно раз в 250 мс. Небольшая сетевая задержка допустима: телефон ждёт подтверждения нажатия, затем показывает новую раскладку. При потере связи таймер замораживается; после восстановления мастер нажимает «Продолжить».

Игроки открывают GitHub Pages. Сервер связи работает в фоне: браузеры сами отправляют ему команды, переходить на его адрес или регистрироваться не требуется. В `public/config.js` указан адрес API. Исходник обработчика и SQL-схема находятся в `relay/`. GitHub Pages публикует HTML, CSS и JavaScript, поэтому передачу команд между устройствами обеспечивает отдельный сервер.

К комнате привязывается одна телефонная консоль. Перезагрузка той же вкладки восстанавливает её идентификатор и ключ; для другого телефона создай новый сеанс. Прогресс раунда остаётся в памяти компьютера и не переживает перезагрузку страницы.

## Локальный запуск и проверка

Требуется Node.js 22 или новее, дополнительных пакетов нет.

```sh
npm start
# http://localhost:4173

npm test
```

По умолчанию сервер слушает порт `4173`. Можно задать переменную `PORT`. Для игры с телефона используй HTTPS-публикацию. Режим локальной проверки на одном компьютере не требует сервера сеансов.

Проверки покрывают точные границы 10/15 секунд, полную перестановку клавиш, правильные и неверные команды, устаревшие сообщения, паузу и отсутствие ответа в телефонном состоянии.

## Файлы

- `public/index.html`, `style.css` — русскоязычные экраны телевизора и телефона.
- `public/game.js` — состояние испытания и проверка команд.
- `public/link.js`, `public/config.js` — HTTPS-связь через сервер и отдельная локальная проверка.
- `public/app.js` — интерфейс, синхронизация, звук, вибрация, QR.
- `public/vendor/` — зафиксированные версии сторонних библиотек.
- `tests/` — проверки игровой логики и сервера сеансов.
- `relay/` — исходник серверного обработчика и SQL-схема.
- `.github/workflows/pages.yml` — проверка и публикация.
